# 研究结论与实现

本次以工作区原版 Extra Loadout Slots 2.1.0 和本机游戏 3.280.0.0 为依据。

2026-10-26，维护者确认改版 2.1.2 已正常工作。此前同一轮测试明确使用官方服务器在线模式，成功反馈未另行重复模式，也未附逐地图、逐武器、逐弹药的测试明细。原始反馈及其范围见 [实机反馈记录](../research/playtest.json)；安装和操作方法见 [README](../README.md)。

## 原版如何增加物品栏

原版包含三个菜单 JSON 补丁和五个新菜单 blob，没有武器实体、弹药、REPO 或 unlockables 补丁。

`context_loadout.JSON.patch.json` 在准备页生成可增长的额外槽位，把槽位列表暂存在 `$loadoutslot 0` 的 `Item.unlockable.slotsData` 中。编辑额外槽时通过 `stashpoint` 物品选择页暂用槽位 5，随后恢复它。

`planning_page.JSON.patch.json` 将所选物品组装为一个临时 Unlockable；`extraslots_repositoryids_constructor.json` / `_sub.json` 按数量展开物品的 `Properties.RepositoryId` 或 `RepositoryAssets`，形成 `Properties.RepositoryAssets` 数组。数量、删除和临时槽位恢复都是原作者的实现，本改版保留了这些文件的原始字节。2.1.2 在 `stashpointslot.JSON.patch.json` 的原始操作之后追加新分类操作。

这说明原版没有赋予某把枪新的穿墙能力。用户观察到的特殊弹药来自被装入任务的武器本身。原版改用 stashpoint 页面作为选择入口，可能使在线物品清单中已有的狙击模式条目可被选择；本次没有抓取用户当时的在线响应，不能确定那次具体选择了哪个 Unlockable 或服务端用了哪条筛选规则。

## 三把武器和奖励版的区别

实际 REPO 文件：`00204D1AFD76AB13.REPO`，本机最新来源为 `chunk0patch4.rpkg`。

| 地图／武器 | 狙击模式 Repository ID | Runtime |
| --- | --- | --- |
| Himmelstein / Sieger 300 Ghost | `5f5e10e1-4c38-4fd0-ac16-8f42526ab232` | `0001BD7A2263A50C` |
| Hantu Port / Druzhina 34 ICA | `c8b2d7ab-c952-4ad3-99fe-4627047318b9` | `00B2EF154AF811DA` |
| Siberia / Druzhina 34 ICA Arctic | `2f209936-1427-43b6-9812-d6f60b24336f` | `00B2EF154AF811DA` |

三者的 `PrimaryConfiguration.ID_` 均为 `7b6eeaeb-c504-4af8-9374-432e0ae8f7f7`，包含以下弹匣：

| 弹匣 | Repository ID | 标签 |
| --- | --- | --- |

穿墙弹的 AmmoConfig 是 `87ae0524-2f22-4fe0-82e1-84a050b43cf0`，进一步引用 `565885d4-1b37-4767-85a4-d83b2fd41bbc`：`Type=eAB_Penetration`，`PenetratesBodies=true`，`PenetratesEnvironment=true`。这里能明确区别“穿透人体”和“穿透场景墙体”。

震荡弹的 AmmoConfig 是 `9d1b189d-ca04-446c-8714-7b2ae137424e`，引用 `1f167090-14c4-4017-b9f6-489e5900aa41`：`Type=eAB_Explosive`、`MassImpulseType=eMIT_ShockWave`。这是原游戏的震荡效果，不是麻醉弹。

故事模式的 ICA／Arctic 奖励条目分别指向 `80407440-c8e3-43cc-8da3-afbe217793a5` 和 `26605ee6-6e82-4a57-909f-76b91e7d93ed`。它们的 PrimaryConfiguration 只有普通奖励版弹匣，因此只凭外观或名称不能判断是否是狙击模式版本。尤其 Arctic 奖励版的 SecondaryConfiguration 仍有特殊弹匣，但其主要配置并不是狙击模式原版；本改版没有依赖这种残留配置。

上述三把狙击模式武器不在本机默认离线 `config.unlockables` 的物品列表中，但完整武器定义已经存在于 REPO。两类武器 Runtime 和两种特殊弹药的效果 TEMP 均在公共 `chunk0` 系列文件中，所以本次无需把整张狙击地图的资源搬入故事地图。

## 改版如何开放选择

**2.1.1 的用户反馈：官方服务器在线模式下，新增条目没有出现。** 已核对本机 SMF 仅启用改版、部署成功，并从实际 `chunk0patch300.rpkg` 解出页面补丁确认与工作区一致。因此安装错误可以排除，前一版静态测试也不能证明该页面改写进入了实机渲染路径。

2.1.1 的实现是在 `007F1E69F079CD50.JSON`（`stashpoint_page.json`）内改写 `LoadoutItemsData` 输入。在线 `/stashpoint` 返回值可以携带整个页面模板；例如 [Peacock 的菜单路由](https://github.com/thepeacockproject/Peacock/blob/master/components/menuData.ts) 和 [H3 页面模板](https://github.com/thepeacockproject/Peacock/blob/master/static/H3StashpointTemplate.json) 展示了这种架构。这是第三方实现的证据，不是用户官服响应的抓包，不能据此声称已完全证明官服内部的具体失败原因。最初怀疑的布尔条件问题也没有被实机单独证实。

**2.1.2 的处理：撤掉页面输入改写，直接修改原版使用的物品叶组件 `00595CD49B4ACA64.JSON`（`stashpointslot.json`）。** 先执行原作者的临时槽位 ID 修正，再把新分类插入现有 `sub_category_controller` 的 children 前方。原生 `$each $.GroupedItems` 分类树按原样保留，没有替换服务器返回的物品列表。

`extraslots_snipertrio_category.json` 生成独立的“狙击模式”分类和三个固定物品 tile。展示直接引用已有武器图片、Perks 和新增的本地化名称；装备动作传递完整 Item，使用 `$.@global.args.slotid` 作为目标槽位，保留机构藏匿点设置和返回准备页的动作。

`extraslots_snipertrio_eligible.json` 排除预留槽位 0–5、空槽位 ID 和原版的额外槽位临时 UUID；槽位 6 只接受大型藏匿点标记（布尔 `true` 和 URL 字符串 `"true"` 都处理），其余游戏提供的动态手提箱槽位允许显示新分类。保留普通分类，空服务器物品列表也可显示新分类。此处只处理游戏实际使用的槽位格式，并不是任意输入的 UUID 验证器。

三把枪使用稳定的独立 Unlockable ID、Guid 和 InstanceId，`Type=weapon`、`Subtype=sniperrifle`、`LoadoutSlot=carriedweapon`，RepositoryId 指向上表的原版武器。菜单直接构造所需条目，无需修改服务端解锁清单，也不替换奖励枪。修复后维护者确认 Mod 正常工作；这证明本次改动解决了其测试环境中的问题，但没有提供所有任务和装备组合的兼容性结论。

## 验证与限制

`research/verification.json` 保存了实际游戏数据的证据链及 SHA-256。2.1.2 的 165 个模拟用例覆盖动态手提箱槽位、大型／小型藏匿点、预留槽位、空列表、布尔和字符串标记，并核对三个装备动作的武器 ID 和目标槽位。模拟器只实现新增表达式用到的运算符，并非完整游戏菜单运行时；它不能预测所有官服行为。

SMF 2.33.42 完成独立部署。随后重新解包 `chunk0patch300.rpkg`，核对三个 JSON 补丁的最终内容、7 个 blob 的 ORES 注册以及英文／简体中文／繁体中文文本。验证副本安装前会清除工作区内的旧副本，防止 2.1.1 文件混入。

验证环境使用工作区内的独立 Runtime 和 Retail，只有菜单构建所需的原始资源。这样隔离是必要的：SMF 的 `src/main.ts` 即使启用 `outputToSeparateDirectory`，仍会清理配置的 Runtime 中的 patch200–300；因此不能只打开该选项就拿实际游戏目录做无改动测试。

2.1.1 已经由用户实测为未生效；2.1.2 在 2026-10-26 收到维护者“Mod已经正常工作”的反馈。`research/verification.json` 记录资源与静态检查，`research/playtest.json` 单独记录实机反馈，二者证据范围不同。本改版未改变游戏按键、弹匣数、武器升级或精通设置。

离线模式、Peacock 服务器、手柄、其他游戏平台、全部任务／起点组合、其他菜单 Mod 的兼容性和卸载后任务存档恢复均未逐项验证。后续若扩展测试，可对三把枪分别记录：选择 → 进入任务 → 取出 → 切换弹药 → 验证穿墙／震荡 → 回装。现有成功反馈不应扩写成没有记录的逐项测试结果；成功生成 RPKG 也不能单独当作实机通过。
